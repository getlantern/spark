Evaluated two candidate transports for spark's M11 ("additional transports behind the `Transport` trait"). Researched 2026-06-16.

**AnyTLS** — proxy protocol gaining traction in China; defeats the **TLS-in-TLS fingerprint** (Xue et al., USENIX Security 2024) via a server-pushable record-size **padding scheme** + **stream mux + idle-session pool**. Does NOT address JA3/active-probing (punts to host platform's uTLS). Reference: `anytls/anytls-go` (Go, **no visible license** → clean-room from spec). sing-box ≥1.12 + mihomo support.
- **Rust impl EXISTS**: `ssrlive/anytls-rs`, published on crates.io as **`anytls`**, **MIT**, maintained (v0.3.5 Jun 2026), stack = `rustls 0.23` + `tokio-rustls` + `tokio`, edition 2024, no openssl/reqwest/hyper — near-perfect fit for spark's locked stack. ⚠️ **v0.3.x REMOVED multiplexing** (deadlock risk) — but mux is the load-bearing evasion property per Xue (padding alone is detectable). Archived `QIN2DIM/anytls-rs` (MIT) still has mux.
- Caveats: unshaped downlink, first-RTT burst-timing leak, no cert masquerade, no active-probe defense → not a complete evasion solution alone; pairs with (doesn't replace) REALITY.

**getlantern/samizdat** — Lantern's OWN Go censorship-resistant protocol (author myleshorton), actively maintained, **already in production via `lantern-box`** (sing-box type `"samizdat"`). Opposite approach to the same fingerprint: **single TLS 1.3, no TLS-in-TLS** — proxies flows as **H2 CONNECT streams muxed inside one outer TLS session** (structurally avoids the inner-TLS handshake). Plus REALITY-style auth in the TLS **SessionID** (`PSK=HKDF(serverPubKey,shortID)`, `SessionID=shortID‖nonce‖HMAC(PSK,nonce)[:16]`), **masquerade fallback** to the real cover domain on bad auth/probe (tlsmasq lineage), uTLS Chrome ClientHello, Geneva-style ClientHello fragmentation, timing jitter. TCP-only (Russia/TSPU). Clone studied at `/tmp/samizdat-research`.

**Key strategic point:** samizdat's design is ahead for pure evasion (avoids TLS-in-TLS structurally + covers cert/SNI + active probing); AnyTLS's edge is ecosystem interop (large sing-box/mihomo installed base in China).

**Hard constraint for BOTH (RESOLVED 2026-06-16 — rustls/uTLS investigation):**
- **rustls CANNOT do ClientHello mimicry or SessionID injection — by maintainer design, not a gap.** JA3/JA4 request closed "not planned" (rustls #2498, 2025-06-16); rustls deliberately *randomizes* extension order to resist parroting; no API for cipher/ext order, GREASE, or `legacy_session_id`. The one fork that added CH shaping (`craftls`, 3andne) is **DEAD** (stuck on rustls 0.22, abandoned Jan 2024) and lacked SessionID anyway.
- **Only working Rust mimicry path = BoringSSL via `boring`/`tokio-boring`.** But: (1) **busts spark's <3 MB budget alone** (~1.5–3 MB+ C/C++ + C++ STL link, harder mobile cross-compile); (2) **arbitrary SessionID is NOT in `boring`'s public API** (`set_session`=resumption only, `id()`=read-only) → needs a *patched* BoringSSL fork. Whole Rust impersonation ecosystem (`wreq`/`rquest`/`reqwest-impersonate`) uses boring, not rustls; no production rustls-based JA3 mimicry exists; no Rust REALITY/sing-box port (same reason).
- **Lantern has NO Rust TLS-mimicry prior art** (confirmed; user confirmed "no existing Rust stack"). Org Rust repos: only `balboa` (prototype, *rewrites* handshakes, no TLS 1.3) and `mirage` (offloads CH to a CDN/Go-WATER host, vanilla tokio-rustls). Mimicry lives only in Go (samizdat uses `refraction-networking/utls`: `BuildHandshakeState` → mutate `HandshakeState.Hello.SessionId` → `MarshalClientHello`).
- rustls DOES support **ECH** (hides SNI; mihomo recommends it for AnyTLS) — solves SNI privacy, not browser-CH mimicry.

**DECISION DIRECTION:** **AnyTLS = right M11 transport now** — rustls-native (anytls-rs proves it), in-budget, proves the trait, no stack change; keep the mux. **samizdat = separate strategic call**, architecturally incompatible with locked rustls on TWO axes (browser CH + SessionID); options if pursued: (a) FFI/subprocess-bridge the Go samizdat client, (b) adopt `boring` for a mimicry-build variant (relax <3 MB, verify/patch SessionID), (c) rustls-compatible samizdat *variant* moving auth out of SessionID (still can't do Chrome CH → only half-solves). Relates to `core/src/transport/mod.rs` (`DirectTransport`, `TunnelClient`). samizdat Go ref cloned at `/tmp/samizdat-tls` (auth.go, client.go).

**BUDGET RELAXED (2026-06-16):** the <3 MB cap is NOT hard — full app may be up to ~10 MB. This makes `boring`/BoringSSL (~1–3 MB) viable for mimicry transports.

**TLS-BACKEND INVESTIGATION COMPLETE (2026-06-16) — decision matrix across rustls/boring/Cronet/OS-native:**
- **rustls:** smallest/pure-Rust/uniform, but identifiable FP + can't do samizdat/REALITY. Fine for AnyTLS.
- **Cronet** (Chromium net stack): genuine Chrome FP + carries tunnel via H2/H3 CONNECT (naive-style; naiveproxy is the proof), and **`getlantern/cronet` fork already exists** (adds WebTransport). BUT 8–15 MB/arch, **iOS dropped by Google at M108 → fork-and-maintain**, owns the socket (no AnyTLS/samizdat). Wick uses Cronet from Rust (GET-only, hand FFI, prebuilt lib, 11 MB macOS bin).
- **OS-native TLS:** ~0 size on Win(SChannel)/Apple(Network.framework), but **Android=impractical** (no NDK TLS API → per-record JNI to SSLEngine), **Linux=absent**, per-OS fragmented FP, and **no OS stack permits SessionID injection** (kills samizdat/REALITY). Niche: iOS-only AnyTLS camouflage. native-tls is banned by locked stack anyway.
- **`boring` (BoringSSL) = the strategic pick.** Raw TLS socket → fits Transport trait, unlocks AnyTLS+samizdat+REALITY+uTLS-mimicry, ~1–3 MB, uniform incl. iOS (C/cmake build).

**CHROME-MIMICRY FIDELITY — EMPIRICALLY PROVEN (2026-06-16 spike, `/tmp/btls-spike`):** stock `cloudflare/boring` 5.x already does cipher/curve/sigalg order, extension permutation, GREASE, brotli cert-compression, **PQ X25519MLKEM768**, ECH GREASE — misses only **ALPS** (the one JA4-shifting gap). The maintained fork **`btls`/`btls-sys`/`tokio-btls`** (0x676e67, was boring2/boring-sys2; Apache-2.0 OR MIT, on crates.io) patches ALPS+ZSTD+record_size_limit. Per-Chrome profiles live in **`wreq-util`** (`Emulation::Chrome137`), wired up by **`wreq`** (the actual maintained mimic; raw tokio-btls has no profile). **Spike result:** `wreq Emulation::Chrome137` → tls.peet.ws/api/all produced **JA4 `t13d1516h2_8daaf6152771_d8a2da3f94cd`, peetprint `1d4ffe9b…`, H2 Akamai `1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p` — BYTE-IDENTICAL to a real Chromium 149** (captured via Playwright, same endpoint), incl. ALPS `44cd`+ECH `fe0d`. Only JA3 differs (expected — GREASE/order randomized per-connection; JA4 is the stable one). **Chrome137 profile == Chrome149 browser → Chrome FP changes far slower than version #, so profile staleness barely affects detectability.**

**CADENCE / DEPENDENCY RISK (research 2026-06-16): MEDIUM overall, but fingerprint-staleness specifically LOW.** wreq-util tracks Chrome ~1–4 weeks behind (newest profile Chrome148 on the 3.0-rc line; stable crate 2.2.6 = Chrome137; Chrome stable = 149), with one ~3-month stall (Feb–May 2026, during the boring2→btls/rquest→wreq renames). **Solo maintainer (0x676e67), bus factor 1, no org backing, pre-1.0/-rc, ~yearly disruptive renames.** Escape hatch: `curl-impersonate` (lexiforest, chrome146+H3, better-resourced, 2.6k stars). Mitigations: pin/vendor versions, ship a CI JA4-drift check (= the spike), keep curl-impersonate as fallback, budget to self-port a profile during stalls.

**curl-impersonate vs btls (decided 2026-06-16): btls is the better PRIMARY dep for spark; curl-impersonate is NOT better for the tunnel core.** Both are byte-exact BoringSSL Chrome mimics (both = equal exception to the rustls-only lock), so quality isn't the axis — integration SHAPE is. curl-impersonate = `libcurl` (HTTP CLIENT, Cronet-class — tunnel *over* it); btls = native-Rust TLS LIBRARY giving a clean tokio AsyncRead+AsyncWrite raw socket that drops into `Transport::dial→BoxedStream`. curl-impersonate's raw path (`CONNECT_ONLY`+`curl_easy_send/recv`) gives **no TLS-record-size API** (AnyTLS-hostile — AnyTLS sizes records per write) and **no SessionID injection** (samizdat/REALITY out without patching the fork); plus it fights tokio (borrowed C fd, TLS-cache drain, CURLE_AGAIN cross-direction, IoC reactor), has **no maintained Rust binding** (curl_cffi=Python; ratcurl=dead/old-fork; impersonate-rs=1★ req/resp), is heavier (curl+nghttp2+ngtcp2 atop BoringSSL), and a worse mobile build. curl-impersonate WINS on: longevity/community + **H3/QUIC mimicry** (chrome145/146 H3; btls/wreq = TLS-over-TCP only). **Verdict: btls primary; curl-impersonate = shelf reference for a future QUIC/H3-mimicry transport + naive-style CONNECT fallback.**

**RECOMMENDED PLAN:** rustls stays the baseline; add **`btls` for mimicry transports** (amends the locked stack: C BoringSSL/cmake, accepts ~1–3 MB). First M11 transport = **AnyTLS-on-`btls`** (AnyTLS brings its own mux+padding to beat TLS-in-TLS — the dominant passive threat per Xue USENIX'24, which no CH-perfection addresses — and btls gives the near-genuine Chrome CH that fixes AnyTLS's one weakness). Later: full multiplexed H2-CONNECT (naive-style on btls) for behavioral realism. samizdat becomes buildable on btls too (raw socket + SessionID via the fork) if pursued.
