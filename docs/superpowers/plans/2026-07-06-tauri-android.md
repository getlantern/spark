# Tauri-on-Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the existing Tauri/SvelteKit UI (`gui-tauri/`) as a native Android VPN app at full feature parity with desktop, by extracting VPN control into one cross-platform Tauri plugin (`tauri-plugin-spark-vpn`).

**Architecture:** The plugin is the unprivileged control client on every platform, behind a `TunnelControl` Rust trait. `AppleControl` (macOS) is CROSS-PROCESS to the system extension (the migrated `ne_spike`); `AndroidControl` (new) is IN-PROCESS to a foreground `VpnService` via JNI; `ServiceControl` (Windows/Linux) is a future cross-process stub over `spark-ipc`. Durable settings persist app-side (shared Rust, platform-provided dir); delivery/live-update/status differ per transport behind the trait.

**Tech Stack:** Tauri v2 (desktop + mobile), Rust (plugin), Kotlin (Android `VpnService` + `@TauriPlugin`), objc2 (macOS NE), SvelteKit (unchanged), cargo-ndk + Android NDK, `spark-core`/`spark-android` (existing).

**Base branch:** `fisk/tauri-android` (stacked on the routing-mode work it depends on). Spec: `docs/superpowers/specs/2026-07-06-tauri-android-design.md`.

**Verification discipline:** Tauri v2 mobile-plugin macros, the activity-result API, permission-JSON schema, and `tauri android init` output are version-sensitive. Phase 0 pins them against current docs and records the exact signatures the later tasks consume. Do NOT hand-write Tauri plugin API code before Phase 0 records the verified forms.

## File Structure

**New — the plugin** (`gui-tauri/tauri-plugin-spark-vpn/`):
- `Cargo.toml` — plugin crate; `build.rs` (Tauri plugin build) — permission codegen.
- `src/lib.rs` — `init()` plugin builder, command registration, platform dispatch wiring.
- `src/error.rs` — `thiserror` `Error`/`Result` for the plugin boundary.
- `src/models.rs` — serde types shared FE↔plugin (`Status`, `ServerInfo`, `SplitTunnel`, `RoutingMode`) — mirror the existing TS shapes.
- `src/control.rs` — the `TunnelControl` trait (the seam).
- `src/persist.rs` — cross-platform durable settings (moved from `config.rs`), platform-provided dir.
- `src/commands.rs` — `#[command]` fns dispatching to the active `TunnelControl`.
- `src/desktop.rs` — `AppleControl` (macOS, the moved `ne_spike`) + `ServiceControl` Windows stub, cfg-branched.
- `src/mobile.rs` — `AndroidControl`: forwards to Kotlin via the mobile bridge.
- `android/` — Gradle library: `SparkVpnPlugin.kt` (`@TauriPlugin`), plus the migrated `SparkVpnService.kt`, `VpnController.kt`, `SparkBridge.kt`; `src/main/AndroidManifest.xml` (permissions + `<service>`).
- `ios/` — stub Swift package dir (no impl this milestone).
- `permissions/` — capability JSON enabling the commands.

**Modify:**
- `gui-tauri/src-tauri/src/lib.rs` — remove `ne_spike` + `spark_*` command bodies; `.plugin(tauri_plugin_spark_vpn::init())`; keep UI-shell only.
- `gui-tauri/src-tauri/src/config.rs` — remove the persistence moved to the plugin (keep `resolve()`/`servers_from_config()` dev-override logic if still used, else move too).
- `gui-tauri/src-tauri/Cargo.toml` — depend on the plugin.
- `gui-tauri/src-tauri/tauri.conf.json` + `capabilities/*.json` — enable the plugin's permissions.
- `gui-tauri/src/lib/tauri_backend.ts` — invoke `plugin:spark-vpn|*` command names.
- `docs/STATE.md` — record the milestone + demo retirement.

**Delete:** `platforms/android/demo/` (after Android parity verified).

**Reuse (unchanged):** `spark-core`, `platforms/android/src/lib.rs` (JNI), `spark-ipc`/`spark-service` (future), `packaging/macos/build-tauri-dmg.sh`, `docs/smart-routing-on-device-validation.md`.
